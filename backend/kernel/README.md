# backend/kernel — the map

The core: agents, tools, artifacts, desks. Plain JS, no host dependency (server, tab, test). Outside code imports
`backend/kernel/index.js` only. Paths below are from the repo root; `<…>` in the persisted column is a placeholder.

## (d) The prompt

`Agent.render` (`backend/kernel/agent/agent.js`) writes every step's prompt in the owner's reading order (2026-10-17
owner: "soul, agent instructions, context, quest, history, tools and response format"): who the agent is, what it
is for, what it holds, what is asked, what was done, what it can call, how to reply. Optional parts are left out
when empty; the order of the rest never changes (`backend/kernel/test/prompt.test.js`).

| # | Part | Section |
| --- | --- | --- |
| 1 | soul | `config.soul`, desk-wide, no header (the prompt opens on it) |
| 2 | agent instructions | `# YOU ARE <name>` + `config.role` |
| 3 | tools | `# TOOLS` (the brief's fields first when it holds agents; an optional field `name?`; tools that describe alike share one line `- a.run \| b.run {…} — …`; right after who it is: with the soul and role, the stable start a provider caches across steps (2026-10-25 owner: "Tools first, RESPONSE last")) |
| 4 | context | every artifact the agent holds, `# <id> — <title>` (the title alone when it starts with the id), in its artifact order (`buildAgent`: least-changing first, the board last) |
| 5 | quest | `# REQUEST (from <who>)`, then `# OWNER GUIDANCE` directly under it while a note waits (guidance amends the quest) |
| 6 | history | `# EARLIER RUNS`, then `# WORK DONE ON THIS REQUEST` (this run's steps, newest last; each result `tool {input} → output`, the input's fields on one line, ≤ 120 chars each) |
| 7 | response format | `# RESPONSE` (`RESPONSE_FORMAT`, + `REPORT_FORMAT` when `config.report`), or `# SYSTEM` when `config.system` replaces it |

2026-10-17 owner ("talk with the lead to understand what is currently already there and what I want to check"):
`Agent.chat` renders the same parts with `render(request, steps, {chat})` — 4 is the run's request, or
`# REQUEST` "(idle: no run in progress)" — and replaces 7 with `# OWNER CHAT` (the last 6 exchanges, each side ≤ 800
chars, then the owner's words) and `# RESPONSE` = `CHAT_FORMAT` (plain prose, no calls; one last `GUIDE:` or `QUEUE:`
line, on its own — not quoted, listed or in a code block — when the owner asks for something done; a QUEUE is a
proposal the owner starts). Without options the step's prompt is byte-identical (prompt.test.js).

Compaction (2026-10-22 owner: "check the size of the before sending and if it is 90%, we autocompress and send the
compressed + goal"): before each step's model call the rendered prompt is measured against the agent's budget
(`agent.budget`: `config.contextChars`, else `contextBudget(config.model)` — Apple's on-device 12k chars, a small local
model 100k, the rest 400k). At `COMPACT_AT` (0.9) of it, `#compact` folds 5 — the run's steps but the newest two, and its
`# EARLIER RUNS` — into one step `(compacted: …)` whose result (tool `compact`) is a summary: one model call over
`# COMPACT` + the request + the folded work (≤ 60% of the budget), or, when that call fails (not a stop), the code-side
fold (each step's thought and results' heads); ≤ 6000 chars. 4 (`# REQUEST`, `# OWNER GUIDANCE`) is never folded: the
goal goes out verbatim. A folded history stays out of the run's later prompts (`current.historyFolded`); a later
compaction folds the earlier summary in. Nothing to fold → the prompt goes as it is. Event `compact {n, before_chars,
after_chars, budget, steps_folded, runs_folded, mode: model | clip, ms, prompt_chars?, reply_chars?, error?}` → its
twin: a row `{action: compact}` in the agent's thread and the Live feed (`backend/live/team-rows.js` `compactLine`;
kind `compact`, its look slate + shrink), the summary's model call in the stats. Tests: `backend/kernel/test/compact.test.js`.
The context meter (2026-10-26 owner: prompt length is the limit): every `render` measures its prompt by element and keeps
only the newest measure in `agent.promptParts` — `[{label, chars}]`, one per part in prompt order (`soul`, `you`,
`tools`, each artifact by its exact id — `dev` and `dev.board` are two parts —, `request`, `guidance`, `earlier runs`,
`work done`, `response`, `other`), the joining blank lines counted, so the chars sum to the prompt's length. The step
event carries it as `promptParts`; its twin keeps the newest one in the agent's stats (`backend/live/team-rows.js`
`nextStats`) and draws it as a stacked bar with a top-3 legend (`backend/live/prompt-meter.js` `meterOf`,
`components/kernel/prompt-meter.jsx`). Tests: `backend/kernel/test/prompt-parts.test.js`, `backend/live/prompt-meter.test.js`.
Response contract (2026-10-26): a run's final answer is checked against its fields — `REPORT_FIELDS` when `config.report`
is set, plus a workflow phase's report fields (the `ask` option `contract`) — by `contractOf(answer, fields)`
(`agent/report.js`: a field is held when a line starts with `field:`, `**field**:` allowed). Only the newest check is kept,
in `agent.answerContract` — `{fields, missed}`; a run with no fields sets none. The step event carries it as `contract`,
the twin keeps the newest in `stats.contract` (`nextStats`) and draws it with `components/kernel/contract-line.jsx`.
Report object (2026-10-26): the same answer's held fields parsed as `{field: value}` by `reportOf(answer, fields)`, newest only, in `agent.answerReport` — the step event's `report`, the twin's `stats.report`, drawn as rows by `ReportRows`.
Tests: `backend/kernel/test/response-contract.test.js`.
