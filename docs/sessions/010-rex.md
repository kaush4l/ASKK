# 010 Rex (Superlogical): decisions to take and to avoid

Rex is closed source (`superlogical.com/rex`). `009`'s two "rex" repos are other projects.
**Evidence:** docs only, read 2026-11-10 (CLI, Server API, Program Status Protocol, Agents,
Lua Events, Server Modes, Privacy, Community MCP). **No REA runtime evidence yet**: the macOS
app is invite-only behind Discord login and is not installed here. §5 is the runtime plan.

## 1. Rex's model

| object | is | askk's nearest |
| --- | --- | --- |
| server | owns everything; keeps sessions alive with nothing attached; Unix socket only by default | the host |
| session | a group of related work (one project) | a place / an engine's folder |
| window | a tab in a session; holds a layout | a route / view |
| block | one application in a window (today: a terminal) | an element, or a session card |
| client | a program connected to the server (Mac app, iOS, CLI) | a shell (`src/shells`) |

Every object has an ID that never changes and is never reused (`block:<uuidv7>`) and an
optional, changeable label.

## 2. Good decisions — take them

| # | decision | why | in askk |
| --- | --- | --- | --- |
| R1 | **Server documents its own API**: `rex api list / describe / call`; JSON Schema in and out, `additionalProperties: false`, request and response examples | CLI, Lua and the agent skill are all derived from it, so they cannot drift | `src/api`: one method registry with schemas; UI, CLI and the agents' MCP tool (`009` T4) generated from it. Test `every_api_method_has_a_schema_and_an_example` |
| R2 | **Every write returns `revision`** | the caller knows which version its change made | store writes return the change-feed sequence (`core/changes.rs`) |
| R3 | **Stable typed IDs** `kind:<uuidv7>`, never reused; labels separate | scripts keep working; logs join; kind visible | `session:…`, `engine:…`, `envelope:…` |
| R4 | **Target order**: full ID → label → position → ID suffix (≥4); ambiguous = change nothing, list matches, exit 3 | humane at a prompt, safe in a script | same resolver for an envelope's `to` |
| R5 | **Fixed exit codes**: 0 ok, 1 fail, 2 usage, 3 target, 4 server unreachable, 130 interrupted; waiters exit with the program's code | callers branch without parsing text | `askk` CLI and `scripts/*.sh` |
| R6 | **Context in env**: `REX_SESSION`, `REX_BLOCK`, `REX_SERVER` in every terminal; commands default to them | a program inside needs no discovery | `ASKK_MEMBER`, `ASKK_HOST` in every harness askk starts; the hook (`009` T1) reads them |
| R7 | **Program Status Protocol (OSC 7501)**: `state=…:kind=permission:msg=<base64>`; unknown keys ignored, last wins, malformed pair skipped | the program that knows its state says it; no scraping; vendor-free | a state source for the `attach` kind (`009` T3); its states map onto `007`'s session states |
| R8 | **Agent setup idempotent**: `rex skill setup --dry-run --json`, reports created / unchanged / updated, leaves the rest of the settings file as it was, `--project` vs account | same as `009` T2, shipped | `askk setup` with the same flags; installs hook + skill |
| R9 | **A session-start hook tells the agent where it is** | saves tokens finding out | `SessionStart` hook injects member id, inbox, brief |
| R10 | **Autostart a personal server; it stops ~10 s after the last session and connection; `REX_AUTOSTART=0` forbids** | zero setup, no orphan daemons | host lifetime rule for the CLI path |
| R11 | **Unix socket only by default**; remote opt-in | nothing listens unasked | host on a socket; HTTP only for the web shell, loopback |
| R12 | **Privacy page lists every outbound connection** | a checkable promise | `docs/privacy.md` |
| R13 | **Handlers fail soft**; `--fail-fast` to stop | one bad event does not end a watcher | change-feed subscribers, desk watchers |
| R14 | **A handler defaults to the event's session, not the script's** | one handler works everywhere | a wake acts on the envelope's member |
| R15 | **Server modes named by who they are for** (personal / shared / login) and exclusive | the trust boundary is the mode, said plainly | one mode (personal), written down |

## 3. Bad decisions — avoid them

| # | decision | cost | askk instead |
| --- | --- | --- | --- |
| B1 | **Misspelled event names are not errors** ("registered and never called") | silent dead handlers | refuse unknown names with the reason (`007` adapt rule 1) |
| B2 | **Failed Lua API call returns `nil, msg`**, does not raise | errors dropped unless checked | `Result` everywhere |
| B3 | **`rex api call` ignores the current session; every other command uses it** | two rules for one context | one default rule for every entry point |
| B4 | **Labels may collide**; scripts told to save IDs | ambiguity pushed onto the user | labels unique per kind and scope, enforced at write |
| B5 | **The PATH dance**: Rex prepends its bin dir, shell startup undoes it, Nix fixes PATH | fragile; another copy may answer | absolute path to the host's tools, `ASKK_BIN` passed explicitly |
| B6 | **Shared server = shared account**: anyone in the group types into every session | no per-session boundary | per-session wall (`008` G8) before any sharing |
| B7 | **Update checks cannot be turned off** | forced outbound connection | every outbound connection has a switch |
| B8 | **Claude runs no hooks until the folder is trusted; Codex asks per hook** | a host relying on hooks silently gets nothing | after setup, check `SessionStart` was seen; if not, the card says "asks not brokered" |
| B9 | **Agents drive Rex by reading terminal screens** | tokens, fragility | structured results through the board |
| B10 | **Start options apply only to a fresh server** (`--max-sessions` ignored if one runs) | a setting that silently does nothing | config is `adapt`ed (`007` §2) or refused with the reason |

## 4. What this changes in the structure

```text
src/api/registry.rs          method → input schema, output schema, examples, handler   (R1, R2)
src/api/cli.rs               `askk api list|describe|call`, from the registry           (R1, R5)
src/core/id.rs               kind:<uuidv7> ids, labels, the target resolver             (R3, R4, B4)
src/host/env.rs              ASKK_MEMBER / ASKK_HOST / ASKK_BIN for every child         (R6, B5)
src/host/setup.rs            `askk setup [--dry-run] [--project] [--json]`              (R8, R9, B8)
src/host/status/osc7501.rs   Program Status reports → session state                     (R7)
docs/privacy.md              every outbound connection and its switch                   (R12, B7)
```

Stages (`005`): R3, R4 at 0 (ids freeze with the envelope); R6, R8, R9, B8 at 1 (the Claude
adapter needs them); R1, R5 when `src/api` is next touched; R7 with the `attach` kind.

## 5. REA runtime pass — once Rex.app is installed

| question | target | REA tool |
| --- | --- | --- |
| What is the app made of; what language is the embedded server? | `/Applications/Rex*.app` | `open_binary` → `inspect_macho`, `inspect_plist`; `inspect_rust_binary` / `inspect_go_binary` on the server |
| How is the local server started and supervised? | app executable | `search_strings` (socket, `XDG_RUNTIME_DIR`), `get_objc_classes`, `analyze_function` |
| The client↔server wire (framing, methods, revisions) | server binary; live socket | `search_strings` for method names; `capture_process_scenario` on `rex api list --json` |
| Agent state: OSC 7501 only, or hooks too? What does the installed hook do? | `rex skill setup --dry-run --json`; the OSC parser | `search_strings` (`7501`, `PermissionRequest`, `SessionStart`), `trace_feature` |
| What survives a server restart? | `~/.local/state/rex`, any SQLite | `inspect_sqlite_database`; `capture_process_scenario` stop/start |
| Outbound connections vs the privacy page | app at launch | `capture_process_scenario` with network capture |

Results go into §6 with Evidence IDs; each R/B row is then marked confirmed, contradicted or
docs-only.
