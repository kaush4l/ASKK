# Raw tool evidence persistence

IndexedDB schema version 2 adds a `toolEvents` store keyed by `[runId, sequence]`. Every raw call and observation is appended once under its immutable identity. Repeating the exact same write is idempotent; replacing that identity with different content fails. New run metadata contains `toolEventStorage: "separate-v1"` and `toolEventCount`, without embedding the growing raw event array. Legacy inline `toolEvents` records remain readable and are not rewritten during schema migration.

Public run reads and trace exports still return the full ordered, frozen `toolEvents` array. The compact model-facing observation does not replace this evidence. An incomplete sequence or a mismatch between stored events and the metadata count fails explicitly; neither missing events nor a retained tail is silently omitted.

`hub.traces.export(trace, { timeoutMs })` filters run metadata before reading the selected trace's event archives. It captures a fixed boundary, waits for those pending event writes and their metadata watermark, and retries failed persistence without executing a tool again. A blocked or failed write rejects the export rather than returning partial proof. The default asynchronous deadline is 15 seconds, configurable up to 60 seconds. Synchronous serialization and final export size are not capped. The returned `toolEventPersistence` distinguishes committed event storage, an in-memory store, and a completed run already evicted by retention.

Retention removes a completed run's metadata and separate events in one transaction after pending writes settle. Active runs are excluded. The existing policy retains 200 stored run records when enough completed runs can be removed. Completed runs still held by the live page remain exportable from memory and are labelled `retention-evicted`; they are not silently written back as orphan events.

Old application tabs can block the v1-to-v2 upgrade. This now fails with a close/reload-other-tabs message, preserving the existing database instead of opening an empty temporary workspace. New connections close on a later version change and require reload before further saves. Genuine unavailable browser storage retains the existing explicit non-durable memory fallback.

This change removes repeated copying of the **raw tool event array** during each run save. It does not make total evidence storage or live memory bounded. Prompts, provider requests, turns, spans and the bounded UI log still reside in the rewritten run record; some contain repeated source or call arguments. Their copy cost remains, and long runs can still exhaust browser quota. Full JSON export also materializes its selected evidence in memory. No evidence was shortened to impose a byte cap.

The motivating synthetic case used 1,000 writes with 100,000 ASCII source bytes each. Its raw call/observation array serialized to 400,522,001 UTF-8 JSON bytes; rewriting that growing array after every event involved 400,722,254,000 cumulative equivalent JSON bytes. Separate appends remove that repeated-array contribution. These figures are not measured IndexedDB disk usage, JavaScript heap size, end-to-end latency, or a claim that other run fields now scale linearly.
