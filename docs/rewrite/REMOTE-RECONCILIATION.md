## Intentional differences and remaining work

A new attempt is not restoration of a process. The hub never automatically resumes interrupted work at startup. The old one-hour/three-resume automatic policy is not carried into a coding harness without declared idempotency. Original run records remain separate; completion verification is not inherited. Existing context pins the original runtime, so a stale binding must be rejected rather than silently rebound. An owner can request a new task on the currently selected runtime instead.

Plans are run-owned and use `todo`, `doing`, `done`, and `dropped`. This prevents parallel roles from racing on one mutable plan. Each prompt receives the current plan without spending a tool call. A new unrelated task starts with an empty plan; explicit continuation carries prior plan state as a claim to recheck. The remote implicit text-identity editing API and result acknowledgement inbox are not implemented. Current `todo.set` publishes in-memory state and requests persistence; a persistence-error event is visible, but the tool does not await durable acknowledgement. Do not describe it as guaranteed durable completion.

Saved conversation goals are separately revision checked and acknowledged only after the storage write. Offline file changes use the current durable CAS journal; Settings can review conflicts and explicitly choose between current runtime bytes and saved offline changes. Goal, transcript, run-plan, and file-journal records have distinct owners, so one generic conversation save cannot overwrite all of them.

Browser failure messages state uncertainty. Direct HTTP loopback can be blocked by browser policy even when a server is running; a configured HTTPS companion is a distinct transport. No generic fetch exception is labeled proof of an offline model, invalid credentials, or a particular browser permission failure.

## Earlier controller audit and disposition

The initial audit identified races between transfers and source writes, binding changes before checkpoint failure, concurrent command/terminal starts, stale build exports, output mutation during packaging, ambiguous pairing, and silent target fallback. Current controller tests exercise controlled interleavings for source and destination mutation, full binary transfer, rollback, reservations, terminal authority, runtime identity, failed replacement builds, and stale checks. Source/build/artifact/command bindings are validated together. Native adapter snapshot races and real browser quota/crash behavior remain integration gates.

The rewrite's offline journal and conflict UI preserve saved browser changes rather than blindly overwriting runtime files during mount. Checkpoint/cache scope remains distinct from a complete backup. A failed durable write must remain visible; compiling code or displaying a green runtime badge is not sufficient evidence to close that gate.
